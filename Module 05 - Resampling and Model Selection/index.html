Module 5, Resampling and Model Selection

How well will a fitted model really perform, and how do we choose which predictors deserve to be in it?

Modules 3 and 4 fit linear and logistic regression models and judged them using training data, R-squared, p-values, residual plots, and confusion matrices. But every one of those numbers was computed on the same data used to fit the model, which can paint an overly optimistic picture. This module introduces tools to honestly estimate how a model performs on new data, and to choose, among many candidate predictors, which ones actually belong in the model.

  • Explain why training error is a poor stand-in for test error
  • Apply the validation set approach and explain its main weakness
  • Carry out leave-one-out and k-fold cross-validation, and explain the bias-variance tradeoff in choosing k
  • Recognize the right and wrong way to apply cross-validation when a model involves a feature selection step
  • Use the bootstrap to estimate the standard error of a statistic
  • Apply best subset, forward stepwise, and backward stepwise selection
  • Use Cp, AIC, BIC, and adjusted R-squared to choose among models of different sizes

Recall, Training Error Versus Test Error

The test error is the average error a fitted model makes on new observations it has never seen. The training error is the error a model makes on the very data used to fit it. Training error is easy to compute, but it is usually far too optimistic.

Why training error misleads: a sufficiently flexible model can fit the training data almost perfectly, memorizing its noise along with its signal, while performing poorly on genuinely new observations. Training error can keep dropping even as test error rises, exactly the overfitting pattern from Module 1 and Module 2.

This module is entirely about getting an honest estimate of test error, or an honest comparison between candidate models, without needing a giant separate test set that most of us never have.

Two Strategies for Estimating Test Error

There are two broad strategies for getting past the optimism of training error.

Indirect adjustment

  • Make a mathematical adjustment to the training error that accounts for model complexity
  • Includes Cp, AIC, BIC, and adjusted R-squared
  • Covered later in this module, alongside model selection

Direct estimation

  • Hold out part of the data from fitting, then measure error on the held-out part
  • Includes the validation set approach and cross-validation
  • Covered first in this module

We start with direct estimation, the resampling methods that give this module its name.

The Validation Set Approach

The simplest direct strategy: randomly split the available data into a training set and a validation set (also called a hold-out set). Fit the model on the training set, then measure its error predicting the validation set, an estimate of test error since the validation observations were not used in fitting.

Worked setup: suppose we want to compare a straight-line fit against several polynomial-degree fits of crop yield on fertilizer amount, using 400 farm plots. We randomly split the plots into 200 for training and 200 for validation, fit each candidate model on the 200 training plots, and compute each model's mean squared error on the 200 validation plots.

Drawbacks of the Validation Set Approach

  • The validation-set estimate of test error can be highly variable, it depends heavily on exactly which observations happened to land in the training set versus the validation set
  • Only a subset of the data, the training half, is actually used to fit the model, which tends to make the validation-set error overestimate the test error of a model fit on the full data set
A concrete illustration: if we repeat the random 200/200 split many times on the same 400 farm plots, each split can suggest a different "best" polynomial degree for the fertilizer-yield curve, sometimes degree 1, sometimes degree 3, simply because of which plots ended up in which half.

Leave-One-Out Cross-Validation (LOOCV)

LOOCV addresses both drawbacks at once. For each observation \(i\), refit the model on all \(n-1\) remaining observations, predict the left-out observation, and record its squared error. Repeating this for every single observation and averaging gives:

\[ CV_{(n)} = \frac{1}{n}\sum_{i=1}^{n} (y_i - \hat y_i)^2 \]

Since each fit uses \(n-1\) of the \(n\) observations, almost the entire data set, LOOCV has far less bias than the validation set approach, and because the procedure is deterministic, it gives the same answer every time, no dependence on a random split.

A Useful Shortcut, and a Real Drawback

Naively, LOOCV sounds expensive, it appears to require fitting the model \(n\) separate times. For ordinary least squares linear or polynomial regression there is a remarkable shortcut, the cost of LOOCV turns out to be the same as a single model fit:

\[ CV_{(n)} = \frac{1}{n}\sum_{i=1}^{n}\left(\frac{y_i - \hat y_i}{1-h_i}\right)^2 \]

where \(\hat y_i\) is the fitted value from the single original least squares fit, and \(h_i\) is the leverage of observation \(i\). Outside this special least-squares case, however, LOOCV genuinely does require \(n\) refits, which can be very costly, and its \(n\) estimates are highly correlated with each other, giving the final average surprisingly high variance.

K-Fold Cross-Validation

A practical middle ground: randomly divide the data into \(K\) roughly equal-sized groups, or folds. Leave out fold \(k\), fit the model on the remaining \(K-1\) folds, and predict the left-out fold. Repeat for every fold \(k=1,\ldots,K\) and combine:

\[ CV_{(K)} = \sum_{k=1}^{K} \frac{n_k}{n}\, MSE_k \]

Setting \(K=n\) recovers LOOCV exactly as a special case. In practice, \(K=5\) or \(K=10\) is far more common, computationally cheaper than LOOCV, and tends to strike a better balance between bias and variance, discussed next.

Choosing K, a Bias-Variance Tradeoff

Each fold's training set in \(K\)-fold CV is only \((K-1)/K\) as large as the full data set, so the estimated test error tends to be biased upward somewhat, the model has slightly less data to learn from than it would in practice. This bias shrinks as \(K\) grows, and is smallest at \(K=n\) (LOOCV).

But there is a cost to large K: LOOCV's \(n\) training sets overlap almost completely with each other, so its \(n\) error estimates are highly correlated, and an average of highly correlated quantities has high variance. \(K=5\) or \(10\) shakes up the data enough to reduce this correlation, giving a good practical compromise between bias and variance.

Cross-Validation for Classification

The same K-fold idea applies directly to classification, simply replace squared error with the misclassification rate within each fold:

\[ CV_{(K)} = \sum_{k=1}^{K} \frac{n_k}{n}\, Err_k, \qquad Err_k = \frac{1}{n_k}\sum_{i \in C_k} I(y_i \neq \hat y_i) \]

This lets us apply exactly the resampling logic from this module to the classifiers from Module 4, logistic regression, LDA, QDA, and Naive Bayes, estimating their test misclassification rate, or comparing several candidate classifiers, without needing a separate giant labeled test set.

A researcher has only 30 observations and wants the least biased possible estimate of test error, computation time is not a concern. Which method should they use?

Cross-Validation, the Wrong Way

Suppose MobiPay's data team has 5,000 candidate behavioral features and only 200 labeled fraud cases. Their pipeline is: (1) from the 5,000 features, select the 80 features most correlated with the fraud label, (2) fit logistic regression using only those 80 features. To estimate test performance, can we simply run cross-validation on step 2 alone, treating the 80 selected features as fixed?

No. Step 1 already looked at every label in the data, including the labels of whatever observations later land in a validation fold. The feature-selection step has effectively "seen" the answers ahead of time, so an estimate that ignores it is badly optimistic, sometimes suggesting a near-zero error rate even when the features have no real relationship to fraud at all.

Cross-Validation, the Right Way

The fix is simple to state, every step that uses the response labels must be redone inside each fold, not just the final model fit.

Wrong

  • Select the 80 best features once, using all 200 cases
  • Then cross-validate only the logistic regression fit on those fixed 80 features

Right

  • Within each fold, hold that fold out entirely first
  • Reselect the 80 best features using only the remaining folds, then fit and validate on the held-out fold

This mistake is common enough that it has shown up in published genomics research, with real test error around 50 percent reported as a deceptively low cross-validation error of nearly 0 percent, simply because the feature selection step leaked label information into the validation process.

The Bootstrap, a Different Resampling Idea

Cross-validation estimates test error. The bootstrap answers a different question: how much would a particular estimate, a coefficient, a mean, a ratio, vary if we had collected a different sample from the same population? It does this by repeatedly resampling from the one data set we actually have.

Where the name comes from: "pulling yourself up by your own bootstraps," from the eighteenth century tale of Baron Munchausen lifting himself out of a lake by his own bootstraps. The method uses the data set to estimate its own sampling variability, with no outside help.

A Motivating Example, Optimal Portfolio Weights

Suppose a fixed amount of money is split between shares of two companies listed on the Dhaka Stock Exchange, with returns \(X\) and \(Y\). Investing a fraction \(\alpha\) in \(X\) and \(1-\alpha\) in \(Y\), the variance-minimizing choice of \(\alpha\) is:

\[ \alpha = \frac{\sigma_Y^2 - \sigma_{XY}}{\sigma_X^2 + \sigma_Y^2 - 2\sigma_{XY}} \]

In practice \(\sigma_X^2\), \(\sigma_Y^2\), and \(\sigma_{XY}\) are unknown and must be estimated from historical return data, giving an estimate \(\hat\alpha\). The natural next question: how much would \(\hat\alpha\) vary if we had collected a different historical sample?

Sampling With Replacement

If we could repeatedly draw brand new samples from the true population of returns, we could compute \(\hat\alpha\) many times and directly observe its variability. With only one real data set in hand, the bootstrap mimics this by sampling, with replacement, from the data set we already have.

Each bootstrap data set: has the same number of observations as the original, but some original observations appear more than once, and others do not appear at all, simply because the draws are made with replacement rather than by splitting the data into disjoint pieces.

Refitting \(\hat\alpha\) on each of these resampled data sets, say \(B=1000\) times, produces \(B\) bootstrap estimates \(\hat\alpha_1^*, \ldots, \hat\alpha_B^*\).

Estimating a Standard Error With the Bootstrap

The spread of the \(B\) bootstrap estimates directly estimates the standard error of \(\hat\alpha\):

\[ SE_B(\hat\alpha) = \sqrt{\frac{1}{B-1}\sum_{r=1}^{B}\left(\hat\alpha_r^* - \bar{\hat\alpha}^*\right)^2} \]

This is the single biggest use of the bootstrap, obtaining a standard error, or a confidence interval, for almost any statistic, even ones for which no clean formula for the standard error exists. The bootstrap percentile interval, taking the 5th and 95th percentiles of the bootstrap estimates, gives a simple approximate 90 percent confidence interval.

Quick Check, What the Bootstrap Estimates

🔎 Quick check

An analyst draws 1,000 bootstrap samples from a single data set of microloan default rates by branch, refits the average default rate on each bootstrap sample, and looks at how much these 1,000 estimates vary. What does this variability primarily tell the analyst?

Why the Bootstrap Is a Poor Tool for Estimating Prediction Error

It might seem natural to use each bootstrap sample as a training set and the original data as a validation set, mimicking cross-validation. This does not work well.

The overlap problem: about two-thirds of the original observations appear, on average, in any given bootstrap sample. Since the "validation" data, the original sample, overlaps heavily with the "training" data, the bootstrap dataset, this approach seriously underestimates the true prediction error, the model is partly being validated on data it already trained on.

Cross-validation remains the simpler and more reliable choice for estimating prediction error. The bootstrap's real strength is standard errors and confidence intervals for a statistic, not test error estimation.

A New Question, Which Predictors Belong?

Modules 3 and 4 generally assumed the set of predictors was already decided. In practice, we often start with many candidate predictors and need to decide which subset to actually include. Adding a predictor can never increase the training RSS or decrease training \(R^2\), so RSS and \(R^2\) alone cannot tell us when to stop adding predictors, since the model with everything in it will always look best by those measures.

A running example: an agricultural research station wants to model rice yield using ten candidate predictors, rainfall, fertilizer dose, soil pH, irrigation frequency, sunlight hours, pesticide use, seed variety, plot size, farmer experience, and previous season's yield. Which of these ten actually belong in the model?

Best Subset Selection

The most exhaustive approach: fit every possible model.

  1. Start with the null model \(M_0\), which contains no predictors and simply predicts the sample mean
  2. For each size \(k=1,\ldots,p\), fit all \(\binom{p}{k}\) possible models with exactly \(k\) predictors, and keep the one with the smallest RSS (equivalently largest \(R^2\)) among them, call it \(M_k\)
  3. Select a single best model from \(M_0, \ldots, M_p\) using cross-validated error, \(C_p\), AIC, BIC, or adjusted \(R^2\)

With \(p=10\) candidate predictors for the rice yield model, this already means fitting \(2^{10}=1024\) different models, one for every possible subset.

Why Best Subset Selection Does Not Scale

Computational cost: the number of possible subsets is \(2^p\), which grows explosively. With \(p=20\) predictors that is already over a million models, with \(p=40\) it is well over a trillion, far beyond what is computationally feasible.

There is also a statistical cost. Searching such an enormous space of models makes it increasingly likely that some subset will fit the training data well purely by chance, even if it has no real predictive power on new data, an overfitting risk that grows with the size of the search space itself.

Forward Stepwise Selection

Forward stepwise selection explores a far smaller, nested sequence of models.

  1. Start with the null model \(M_0\)
  2. For \(k=0,\ldots,p-1\), consider all \(p-k\) models that add one predictor to \(M_k\), and choose the one with smallest RSS, call it \(M_{k+1}\)
  3. Select a single best model from \(M_0,\ldots,M_p\) using cross-validated error, \(C_p\), AIC, BIC, or adjusted \(R^2\)

This requires fitting only about \(1+p(p+1)/2\) models rather than \(2^p\), for \(p=10\) that is 56 models instead of 1024, a dramatic reduction, but the search is greedy: once a predictor is added it is never reconsidered, so it is not guaranteed to find the single best model of every size.

Backward Stepwise Selection

Backward stepwise selection runs the same greedy idea in reverse.

  1. Start with the full model \(M_p\), containing all \(p\) predictors
  2. For \(k=p,\ldots,1\), consider all \(k\) models that remove one predictor from \(M_k\), and choose the one with smallest RSS, call it \(M_{k-1}\)
  3. Select a single best model from \(M_0,\ldots,M_p\) using cross-validated error, \(C_p\), AIC, BIC, or adjusted \(R^2\)
An important restriction: backward selection needs to fit the full model \(M_p\) first, which requires \(n > p\). Forward stepwise selection has no such restriction and remains usable even when \(p\) exceeds \(n\), making it the only viable stepwise option in very high-dimensional settings.

Quick Check, Comparing the Three Strategies

🔎 Quick check

A researcher has 5,000 candidate genetic markers and only 60 patients. Which selection strategy is even feasible here, and why?

Choosing the Optimal Model Size

Every selection procedure above returns a sequence of candidate models, \(M_0, M_1, \ldots, M_p\), one per size. The model containing every predictor will always have the smallest training RSS and the largest training \(R^2\), purely because those measures never penalize adding more predictors. Selecting among the candidates therefore requires either an adjustment to the training error, or a direct estimate of test error, exactly the resampling tools from earlier in this module.

Mallow's \(C_p\) and AIC

\(C_p\) adjusts the training RSS upward by a penalty proportional to the number of parameters \(d\) used:

\[ C_p = \frac{1}{n}\left(RSS + 2d\hat\sigma^2\right) \]

The Akaike Information Criterion (AIC) is defined more generally, for any model fit by maximum likelihood, as \(AIC = -2\log L + 2d\), where \(L\) is the maximized likelihood. For linear regression with normally distributed errors, maximum likelihood and least squares coincide, and \(C_p\) and AIC turn out to be equivalent. Smaller values of either criterion indicate a model expected to have lower test error.

The Bayesian Information Criterion (BIC)

\[ BIC = \frac{1}{n}\left(RSS + \log(n)\, d\hat\sigma^2\right) \]

BIC looks almost identical to \(C_p\), but replaces the penalty \(2d\hat\sigma^2\) with \(\log(n)\,d\hat\sigma^2\). Since \(\log(n) > 2\) for any \(n > 7\), BIC penalizes additional predictors more heavily than \(C_p\) does, and so tends to select smaller, more parsimonious models.

Rule of thumb: as with \(C_p\) and AIC, we select the model with the smallest BIC value among the candidates.

Adjusted \(R^2\)

For a model with \(d\) variables, adjusted \(R^2\) is defined as:

\[ \text{Adjusted } R^2 = 1 - \frac{RSS/(n-d-1)}{TSS/(n-1)} \]

Unlike \(C_p\), AIC, and BIC, a larger adjusted \(R^2\) indicates a model expected to have lower test error. Maximizing adjusted \(R^2\) is equivalent to minimizing \(RSS/(n-d-1)\); while RSS itself always falls as predictors are added, dividing by \(n-d-1\) means this ratio can rise again once unhelpful predictors are added, unlike ordinary \(R^2\), which never penalizes extra predictors at all.

Using Validation or Cross-Validation Instead

Rather than adjusting the training error mathematically, we can directly estimate test error for each candidate model size using the validation set approach or k-fold cross-validation from earlier in this module, then pick the size \(k\) with the smallest estimated test error.

An advantage over Cp, AIC, BIC, and adjusted R-squared: this approach gives a direct estimate of test error without needing to estimate the error variance \(\sigma^2\) or count parameters \(d\) precisely, which can be useful for models where \(d\) is not even well defined, and it places fewer assumptions on the model being fit.

The One-Standard-Error Rule

In practice, cross-validation error often looks roughly flat across several neighboring model sizes, several models may be statistically indistinguishable in their estimated test error. The one-standard-error rule resolves this in favor of simplicity.

  1. Compute the standard error of the cross-validated test error estimate for each model size
  2. Find the smallest estimated test error among all the candidate sizes
  3. Select the smallest model whose estimated test error is within one standard error of that minimum
Rationale: if a six-predictor and a four-predictor rice yield model have statistically indistinguishable estimated test error, the simpler four-predictor model is preferred, fewer predictors to collect and maintain, with no real cost in predictive accuracy.

Comparing the Model Selection Criteria

Cp / AIC

  • Penalizes training RSS by 2d times the error variance
  • Equivalent for least squares with Gaussian errors
  • Tends to favor somewhat larger models than BIC

BIC

  • Penalizes more heavily than Cp/AIC, using log(n)d
  • Tends to select smaller, more parsimonious models
  • Popular when interpretability and simplicity matter most

Adjusted R-squared

  • Larger values indicate a better expected model
  • Penalizes extra predictors less aggressively than BIC
  • Convenient since it is reported by most software automatically

Validation / Cross-Validation

  • Directly estimates test error, no variance estimate needed
  • Works even when "number of parameters" is unclear
  • More computationally expensive, but fewer assumptions

Limitations to Keep in Mind

  • Stepwise selection is greedy and not guaranteed to find the single best model of each size, only best subset selection guarantees that, at a computational cost that is often prohibitive
  • Cp, AIC, and BIC rely on an estimate of the error variance, which can itself be unreliable in small samples
  • Cross-validation, while more direct, can still be misapplied, as the wrong-way example showed, any data-dependent step must be repeated inside each fold
  • None of these methods address what happens when predictors are highly correlated with each other, a problem discriminant and shrinkage methods handle differently

Roadmap to Module 6

Subset and stepwise selection choose a sharp in-or-out subset of predictors. Module 6 introduces an alternative, shrinkage methods such as ridge regression and the Lasso, which keep every predictor in the model but shrink their coefficients toward zero, trading a small amount of bias for a often large reduction in variance, with the Lasso additionally able to shrink some coefficients to exactly zero, performing variable selection continuously rather than in discrete steps.

A thread to keep pulling on: the cross-validation machinery from this module reappears in Module 6, used there to choose the tuning parameter that controls how much shrinkage to apply.
