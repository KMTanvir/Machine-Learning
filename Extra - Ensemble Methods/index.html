Ensemble Methods: A Brief Overview

A single decision tree is interpretable but unstable: refitting on a slightly different sample can change the top split and hence the entire tree. Ensembles fix this by combining many trees, and in doing so produce some of the strongest predictors available for tabular data.

What this module covers

  • Bagging, out of bag error, and why averaging reduces variance
  • Random forests, and the role of the $m_{try}$ decorrelation trick
  • AdaBoost and gradient boosting as forward stagewise additive modelling
  • Bagging versus boosting, and SHAP values for interpreting ensemble predictions
  • A brief overview of modern boosting: the XGBoost objective and hyperparameters, and how XGBoost, LightGBM and CatBoost differ
Where this sits in the course This module builds directly on Modules 18 and 19, since every method here uses CART trees as its building block, and on the bootstrap from Module 15.
Bagging

Bootstrap Aggregation (Bagging)

Bagging algorithm
  1. For $b = 1, \ldots, B$: draw a bootstrap sample $\mathcal{D}^{*b}$ of size $n$ with replacement from $\mathcal{D}$.
  2. Fit a full, unpruned tree $\hat{f}^{*b}$ on $\mathcal{D}^{*b}$ (no pruning: low bias, high variance individually).
  3. Aggregate: for regression, $\hat{f}_{\text{bag}}(x) = \frac{1}{B}\sum_{b=1}^B \hat{f}^{*b}(x)$; for classification, take the majority vote.
Out-of-bag (OOB) error Each bootstrap sample omits roughly $1/e \approx 36.8\%$ of observations. For each observation $i$, form $\hat{f}_{\text{OOB}}(x_i)$ by averaging only over trees where $i$ was not in the bootstrap sample. The OOB error is a valid estimate of test error without a separate validation set: it is essentially cross-validation for free.
Why unpruned trees? Pruning reduces variance but increases bias. In bagging, we want each tree to have low bias (so the aggregate is also low-bias). Variance is handled by averaging $B$ trees rather than by pruning individual trees.
Limitation: correlated trees If one predictor is very strong, it dominates the first split of nearly every bootstrapped tree. The trees are then highly correlated, and averaging correlated estimators gives little variance reduction. Random forests address this directly.
Random Forests

Random Forests: Decorrelating the Ensemble

As the number of trees $B$ grows, test error (orange) stabilises. Using $m < p$ features per split (random forest, solid) achieves lower error than bagging with $m=p$ (dashed).

Random forest modification At each split, instead of searching all $p$ predictors, randomly sample $m \leq p$ candidate predictors and find the best split among only those $m$. Typical defaults: $m = \lfloor\sqrt{p}\rfloor$ for classification, $m = \lfloor p/3 \rfloor$ for regression.
Variance formula With $B$ trees each having variance $\sigma^2$ and pairwise correlation $\rho$: $$\mathrm{Var}\!\left(\hat{f}_{\text{RF}}\right) = \rho\,\sigma^2 + \frac{1-\rho}{B}\,\sigma^2$$ As $B \to \infty$, variance converges to $\rho\sigma^2$. Reducing $m$ reduces $\rho$, which reduces this floor. Reducing $m$ also slightly increases $\sigma^2$ (each tree is weaker), so there is an optimal $m$.
Variable Importance

Variable Importance in Random Forests

Impurity-based importance For each predictor $X_j$, sum the total decrease in node impurity (Gini or RSS) across all splits on $X_j$, averaged over all $B$ trees: $$\mathrm{VI}(j) = \frac{1}{B}\sum_{b=1}^B \sum_{t:\,\text{split on }X_j \text{ in tree }b} \Delta I(t)$$ where $\Delta I(t)$ is the impurity decrease at node $t$ weighted by the fraction of observations reaching $t$.
Permutation importance For each tree $b$ and predictor $j$: record the OOB error on tree $b$, then randomly permute the values of $X_j$ in the OOB sample and recompute OOB error. The increase in error from permuting $X_j$ measures how much the model relies on $X_j$. Average this increase over all trees.

Permutation importance is more reliable than impurity importance for high-cardinality or continuous predictors, which tend to be spuriously favoured in impurity-based measures.
Interpretation Variable importance does not provide a $p$-value or confidence interval. It is a ranking tool. A predictor with high importance is used frequently in splits that substantially reduce error. Low importance means either the predictor is irrelevant or its information is captured by correlated predictors.
Hyperparameters

Random Forest Hyperparameters

Predictors tried per split ($m$)Main tuning knob; typically $\sqrt{p}$ for classification and $p/3$ for regression. Smaller $m$ decorrelates the trees

Does random forest overfit as $B \to \infty$? No. Adding more trees never increases test error (the variance formula shows variance can only decrease or stay constant). The risk is that training takes longer, not that the model gets worse. The minimum node size and $m$ are the true regularisation knobs.
Correlation with test set size OOB error is a reliable estimate of test error only when $n$ is large enough that each tree is built on a substantially different bootstrap sample. For very small $n$, explicit cross-validation is preferred over OOB error for hyperparameter selection.
AdaBoost

AdaBoost for Binary Classification

AdaBoost algorithm ($y_i \in \{-1,+1\}$)
  1. Initialise uniform weights: $w_i = 1/n$ for all $i$.
  2. For $b = 1,\ldots,B$:
    • Fit a weak classifier $G_b(x)$ (typically a depth-1 stump) to $(x_i, y_i)$ with sample weights $w_i$.
    • Compute weighted misclassification error: $\mathrm{err}_b = \sum_{i=1}^n w_i \cdot \mathbf{1}[y_i \neq G_b(x_i)]$.
    • Compute classifier weight: $\alpha_b = \log\!\left(\dfrac{1-\mathrm{err}_b}{\mathrm{err}_b}\right)$.
    • Update observation weights: $w_i \leftarrow w_i \cdot \exp\!\left(\alpha_b \cdot \mathbf{1}[y_i \neq G_b(x_i)]\right)$, then renormalise.
  3. Final classifier: $G(x) = \mathrm{sign}\!\left(\sum_{b=1}^B \alpha_b G_b(x)\right)$.
Weight update interpretation Misclassified observations receive higher weight in the next round; correctly classified ones receive lower weight. Each subsequent weak learner focuses on the observations the current ensemble struggles with. A perfect classifier ($\mathrm{err}_b=0$) gets $\alpha_b \to \infty$; a random classifier ($\mathrm{err}_b=0.5$) gets $\alpha_b=0$ (ignored).
Sensitivity to noise Because mislabelled observations receive ever-increasing weight, AdaBoost is sensitive to label noise. A single consistently mislabelled point can monopolise sample weight and degrade performance. Gradient boosting with regularisation is more robust.
Gradient Boosting

Gradient Boosting: Functional Gradient Descent

Residuals (grey) shrink as boosting iterations increase (left to right). Each new tree (orange) fits the current residuals, not the original targets.

Gradient boosting for regression (squared loss)
  1. Initialise $\hat{f}^{(0)}(x) = \bar{y}$.
  2. For $b = 1,\ldots,B$:
    • Compute negative gradient (pseudo-residuals): $r_i^{(b)} = y_i - \hat{f}^{(b-1)}(x_i)$.
    • Fit a regression tree $h_b$ to $\{(x_i, r_i^{(b)})\}$ with $d$ terminal nodes (stumps: $d=2$).
    • Update: $\hat{f}^{(b)}(x) = \hat{f}^{(b-1)}(x) + \nu \cdot h_b(x)$, where $\nu \in (0,1]$ is the learning rate (shrinkage).
  3. Output $\hat{f}^{(B)}(x)$.
Why "fit the residuals" is gradient descent Boosting lowers the loss by moving the prediction $f$ in the direction of steepest descent, the negative gradient of the loss. For a general differentiable loss $L(y,f)$ the pseudo-residual at step $b$ is $$r_i^{(b)} = -\frac{\partial L(y_i,f)}{\partial f}\bigg|_{f=\hat{f}^{(b-1)}(x_i)}$$ For squared error, take $L(y,f)=\tfrac{1}{2}(y-f)^2$. Then $$\frac{\partial L}{\partial f} = f-y \quad\Longrightarrow\quad -\frac{\partial L}{\partial f} = y-f \quad\Longrightarrow\quad r_i^{(b)} = y_i-\hat{f}^{(b-1)}(x_i)$$ which is exactly the ordinary residual. So for squared loss, fitting each tree to the residuals is gradient descent; the factor $\tfrac{1}{2}$ is only there to cancel the 2 from differentiating.
Other loss functions Because only the pseudo-residual changes, the same algorithm optimises log-loss (classification), absolute error (robust regression), quantile loss and many others.
Regularisation

Regularisation in Gradient Boosting

ParameterEffectOverfitting risk

Learning rate and number of trees trade-off Small $\nu$ (e.g.\ 0.01) with large $B$ (e.g.\ 5000) typically outperforms large $\nu$ with small $B$. The best strategy: fix a small $\nu$, then use early stopping on a validation set to find the optimal $B$.
Boosting can overfit Unlike random forests (whose variance converges), boosting with large $B$ and large $\nu$ can overfit because the model continues to fit residuals that are pure noise. Early stopping and small $\nu$ are essential regularisers. The optimal $B$ is always selected by CV or early stopping, never by inspecting training loss.

SHAP Values

SHAP Values: Explaining a Boosted Model

A boosted model with hundreds of trees is accurate but opaque. Impurity importance says which features the trees used, but not how a feature moved a particular prediction, or in which direction. SHAP answers both.

The idea: a fair split of the prediction Start from the baseline, the average prediction over the training data. The model's actual prediction for one observation differs from this baseline. SHAP divides that difference among the features so that each feature gets a signed share, its SHAP value $\phi_j$: $$\hat f(x) \;=\; \underbrace{E[\hat f(X)]}_{\text{baseline}} \;+\; \phi_1 + \phi_2 + \cdots + \phi_p$$ A positive $\phi_j$ pushed the prediction up from the baseline, a negative one pushed it down, and the size says by how much. The shares always add up exactly to the gap.
Where the shares come from: a team analogy Think of the features as team members who together produce the prediction. To judge one member's contribution fairly, ask what the team's output changes by when that member joins, and average this over every possible order in which the team could have been assembled and over every possible set of teammates already present. This average marginal contribution is the Shapley value from cooperative game theory. For tree ensembles an efficient algorithm (TreeSHAP) computes it exactly, without trying every ordering.
Local explanation The SHAP values for one observation explain that prediction: why was this applicant scored high risk? This is what a loan officer or a patient wants to know.
Global explanation Averaging $|\phi_j|$ over all observations ranks the features overall. SHAP therefore gives both views from the same numbers, which impurity importance cannot.
SHAP explains the model, not the world A large SHAP value means the model relies on that feature, not that the feature causes the outcome. With strongly correlated predictors the credit is shared between them, as with impurity importance, so interpret the shares with the same care.

Why trees do not enumerate orderings With $p$ features there are $p!$ orderings, which is hopeless for $p=50$. TreeSHAP uses the tree structure to obtain the same values exactly without listing them.

Objective

XGBoost: Objective and Hyperparameters

XGBoost is gradient boosting with one addition: each new tree is built to reduce the loss and is penalised for being complicated.

What each new tree minimises $$\text{Loss on the data} \;+\; \gamma T \;+\; \frac{\lambda}{2}\sum_{j=1}^{T} w_j^2$$ $T$ is the number of leaves and $w_j$ is the prediction in leaf $j$. The term $\gamma T$ discourages many leaves, and $\lambda$ shrinks large leaf predictions.
Two summaries per observation For each observation, XGBoost records $g_i$, the slope of the loss (how wrong the current prediction is, and in which direction), and $h_i$, its curvature. For a leaf, add these up: $G=\sum g_i$ and $H=\sum h_i$. Everything below uses only $G$ and $H$.
How XGBoost uses these (for understanding, not memorising)

Best prediction for a leaf:

$$w^* = -\frac{G}{H+\lambda}$$

Gain from splitting a leaf into a left and a right child (split only if the gain is positive):

$$\text{Gain} = \frac{1}{2}\left[\frac{G_L^2}{H_L+\lambda}+\frac{G_R^2}{H_R+\lambda}-\frac{G^2}{H+\lambda}\right] - \gamma$$
In words A larger $\lambda$ shrinks leaf predictions and gains; a larger $\gamma$ blocks splits that do not improve the loss enough. Both make the tree simpler and guard against overfitting.

Key hyperparameters

HyperparameterRole

Choosing the number of trees: early stopping Hold out a validation set and monitor its loss after every boosting round. Stop when the validation loss has not improved for a set number of rounds (say 50) and keep the round with the lowest loss. The training loss always keeps falling, so it can never be used for this choice.
Keep the test set out of it The validation set used for early stopping must be separate from the test set. XGBoost also handles missing values natively, by learning a default direction at each split, so imputation is usually not needed.
Modern Libraries

LightGBM and CatBoost

XGBoost is not the only widely used implementation of gradient boosting. Two others, LightGBM and CatBoost, optimise the same kind of regularised objective but make different design choices to be faster or to handle categorical data better.

LightGBM: built for speed on large data
  • Leaf wise growth. XGBoost expands every node at a given depth before going deeper, giving balanced trees. LightGBM instead splits whichever leaf promises the largest loss reduction, wherever it sits. For a fixed number of leaves this reaches lower training loss, but it grows deep narrow branches and overfits small datasets more readily, so the maximum number of leaves and the minimum observations per leaf matter a great deal.
  • Histogram split finding. Continuous features are grouped into a few hundred bins, so candidate splits are bin boundaries rather than every observed value. This cuts both memory and time.
  • Gradient based sampling. Observations with small gradients are already well fitted, so most of them can be skipped when searching for splits, with little loss of accuracy.
CatBoost: built for categorical predictors Replacing a category by its mean response leaks the target into the predictor, since observation $i$'s own $y_i$ helps build its own feature. CatBoost applies ordered target statistics: it fixes a random permutation and computes each observation's encoding using only observations appearing earlier in that order, so no observation contributes to its own encoding. This is the same principle that motivates keeping feature engineering inside the cross validation loop. CatBoost also grows symmetric (oblivious) trees, where every node at a given depth uses the same split. These are less flexible but very fast to predict with, and they act as a built in regulariser.
Comparison

XGBoost, LightGBM and CatBoost Compared

All three optimise a regularised gradient boosting objective on trees; they differ in how they grow trees, how they find splits, and how they treat categorical predictors.

The three compared

What the differences do not change All three overfit if run for too many rounds without early stopping. Published benchmarks separating them typically differ by less than the variation induced by hyperparameter tuning, so the library choice matters far less than tuning the learning rate, tree depth and number of rounds, and validating honestly. Choose CatBoost when the data is dominated by high cardinality categoricals, LightGBM when training time on large data is the binding constraint, and XGBoost otherwise.

Choosing among tree-based methods Start with a random forest: it is robust, easy to tune, and rarely overfits. What tree-based methods cannot do Tree-based methods are excellent for tabular data with complex interactions and mixed variable types. In-Class Exercise

In-Class Exercise

Bagging and random forests

Questions
  1. In bagging with $B=100$ trees, approximately how many observations are in the OOB set for each tree? (Express as a fraction of $n$.)
  2. Suppose $p=16$ predictors. What are the default values of $m$ for classification and regression random forests? What happens to the correlation between trees as $m$ decreases from 16 to 1?
  3. A random forest with $m=p$ is equivalent to bagging. A random forest with $m=1$ selects one predictor at random at each split. Compare the bias and variance of these two extremes.
  4. Variable importance scores show that $X_3$ and $X_7$ are both highly ranked and strongly correlated with each other. What happens to the importance of $X_3$ if $X_7$ is removed from the dataset? Why?
  1. Each bootstrap sample of size $n$ (with replacement) omits each observation with probability $(1-1/n)^n \to e^{-1} \approx 0.368$. So approximately $36.8\%$ of observations are OOB for each tree.
  2. Classification default: $m=\lfloor\sqrt{16}\rfloor=4$. Regression default: $m=\lfloor 16/3\rfloor=5$. As $m$ decreases, the strong predictors are excluded from more splits, forcing trees to use weaker or different predictors. Trees become more diverse (less correlated), which reduces $\rho$ and therefore ensemble variance, at the cost of each individual tree being noisier.
  3. $m=p$ (bagging): low bias (full trees), but trees are correlated because the dominant predictor appears in nearly every first split. Variance floor is $\rho\sigma^2$ with $\rho$ potentially large. $m=1$ (random single feature): each tree is built from single-feature splits, so individual tree bias is high (cannot model interactions between predictors). However, trees are nearly uncorrelated ($\rho$ small), so the variance floor is very low. The optimum $m$ balances these two forces.
  4. If $X_7$ is removed, $X_3$ will likely absorb much of the importance previously split between the two correlated predictors. When both are present, the random feature subset at each split sometimes excludes $X_3$ and includes $X_7$ (and vice versa), sharing the credit. Removing $X_7$ forces all the splits that would have used $X_7$ to now use the next best alternative, which may be $X_3$, increasing its apparent importance. This is a manifestation of why importance scores should be interpreted with caution when predictors are correlated.

Boosting

Questions
  1. In AdaBoost, a weak classifier achieves $\mathrm{err}=0.3$ on the weighted training set. Compute $\alpha$ and interpret its sign and magnitude.
  2. In gradient boosting with squared loss, the pseudo-residuals are $r_i = y_i - \hat{f}^{(b-1)}(x_i)$. What are the pseudo-residuals for absolute loss $L(y,f)=|y-f|$?
  3. Explain why using stumps ($d=1$) in gradient boosting means the model can only represent additive effects in the first iteration, but can capture interactions in later iterations.
  4. A gradient boosting model with $\nu=0.1$ and $B=100$ achieves the same training loss as one with $\nu=0.01$ and $B=1000$. Which model is likely to generalise better, and why?
  1. $\alpha = \log((1-0.3)/0.3)=\log(0.7/0.3)=\log(2.333)\approx 0.847$. Positive: the classifier is better than random ($\mathrm{err}<0.5$), so it gets positive weight in the final ensemble. Magnitude 0.847: moderate weight. If $\mathrm{err}=0$, $\alpha\to\infty$; if $\mathrm{err}=0.5$, $\alpha=0$; if $\mathrm{err}>0.5$, $\alpha<0$ (the classifier is worse than random and effectively gets flipped).
  2. For $L=|y-f|$: $\partial L/\partial f = -\mathrm{sign}(y-f)$ for $y\neq f$. So $r_i = -\partial L/\partial f = \mathrm{sign}(y_i - \hat{f}^{(b-1)}(x_i))$. Each pseudo-residual is $+1$ (if underpredicting) or $-1$ (if overpredicting), regardless of the residual magnitude. This makes gradient boosting with absolute loss robust to outliers (large residuals do not get extra weight).
  3. At iteration $b=1$: the model is $\hat{f}^{(0)}=\bar{y}$, and the stump fits a single split on one predictor. The update $\hat{f}^{(1)}=\bar{y}+\nu h_1(x)$ depends on only one predictor: purely additive. At iteration $b=2$: the residuals $r_i^{(2)}=y_i-\hat{f}^{(1)}(x_i)$ depend on the first stump's prediction. The second stump may split on a different predictor, and its residuals already encode the first predictor's contribution. As iterations accumulate, residuals that are systematic functions of multiple predictors can be fitted by different stumps, creating an implicit interaction through the residual chain, even though each individual tree is additive.
  4. The smaller learning rate ($\nu=0.01$, $B=1000$) is generally preferred. Smaller steps explore the loss surface more carefully, are less likely to overshoot, and the variance introduced per step is lower. With early stopping based on validation error, the optimal $B$ for the smaller $\nu$ model is found more precisely. In practice, small $\nu$ and large $B$ consistently produce better generalisation than large $\nu$ and small $B$ when both achieve the same training loss, because the small-step model is more regularised.
Practice Problems

Practice Problems

Bagging and random forests

Problem 1: Conceptual
  1. Explain why averaging $B$ trees reduces variance but does not reduce bias. What does this imply about the individual trees in bagging?
  2. True or False: The OOB error always underestimates test error because the OOB sample is smaller than a proper test set.
  3. In a random forest with $B=500$ trees, increasing $B$ to 1000 is unlikely to improve accuracy significantly. Explain why, referencing the variance formula.
  1. Averaging $B$ estimators with mean $\mu$ and variance $\sigma^2$ gives an average with mean $\mu$ (unchanged: bias is not reduced) and variance $\sigma^2/B$ (reduced, if independent) or $\rho\sigma^2+(1-\rho)\sigma^2/B$ (if correlated). Bias is a property of each tree's expected prediction relative to the truth; averaging does not change expectations. This implies each individual tree should have low bias: achieved by growing full unpruned trees on large enough bootstrap samples. The ensemble handles the variance problem.
  2. False. OOB error is not biased downward because of sample size. Each OOB prediction is made by a tree that has not seen that observation during training, so it genuinely measures out-of-sample performance. The OOB set for each observation is about $0.368n$ trees, which is ample for stable prediction. OOB error is widely accepted as nearly equivalent to leave-one-out cross-validation in practice.
  3. From $\mathrm{Var}(\hat{f}_\text{RF})=\rho\sigma^2+(1-\rho)\sigma^2/B$: the first term $\rho\sigma^2$ is independent of $B$. As $B$ grows, the second term $(1-\rho)\sigma^2/B \to 0$. Going from 500 to 1000 reduces the second term by half, but if $\rho\sigma^2$ already dominates (as it does for large $B$), the further reduction is negligible. The variance is essentially at its floor $\rho\sigma^2$, and no amount of additional trees can reduce it below this limit.
Problem 2: Calculation A random forest has $B=200$ trees, each with variance $\sigma^2=0.16$ and pairwise correlation $\rho=0.4$.
  1. Compute the variance of the random forest prediction.
  2. What variance would bagging (same trees but $\rho=0.7$) achieve with $B=200$?
  3. What is the variance floor as $B\to\infty$ in each case?
  4. If reducing $m$ changes $\rho$ from 0.7 to 0.4 but increases individual tree variance from 0.16 to 0.22, which setting gives lower ensemble variance at $B=200$?
  1. $\mathrm{Var}=0.4(0.16)+(1-0.4)(0.16)/200=0.064+0.6(0.0008)=0.064+0.00048\approx 0.0645$.
  2. $\mathrm{Var}=0.7(0.16)+(0.3)(0.16)/200=0.112+0.00024\approx 0.1122$.
  3. Floor ($B\to\infty$): case (a) $\rho\sigma^2=0.064$; case (b) $0.7(0.16)=0.112$. Reduced correlation cuts the floor by nearly half.
  4. Case with $\rho=0.4,\sigma^2=0.22$: $\mathrm{Var}=0.4(0.22)+(0.6)(0.22)/200=0.088+0.00066\approx 0.0887$. Case with $\rho=0.7,\sigma^2=0.16$: $0.1122$ (from b). The lower-correlation setting ($\rho=0.4$) gives lower ensemble variance ($0.0887<0.1122$) even though individual trees are noisier.

Boosting

Problem 1: AdaBoost Three training points with labels $y \in \{-1,+1\}$: $(x_1,+1)$, $(x_2,-1)$, $(x_3,+1)$. Uniform initial weights $w=(1/3,1/3,1/3)$. Stump $G_1$ correctly classifies $x_1,x_3$ and misclassifies $x_2$.
  1. Compute $\mathrm{err}_1$ and $\alpha_1$.
  2. Update the weights. Which observation gets the highest weight?
  3. What does the new weight distribution imply for the second stump $G_2$?
  1. $\mathrm{err}_1 = w_2 = 1/3$. $\alpha_1 = \log((1-1/3)/(1/3))=\log(2)\approx 0.693$.
  2. $x_2$ is misclassified, so its weight is multiplied by $e^{\alpha_1}=e^{0.693}=2$: new weight $\propto (1/3)(1)$, $(1/3)(2)$, $(1/3)(1)=(1/3,2/3,1/3)$. Normalised: $(1/4, 1/2, 1/4)$. $x_2$ has the highest weight (0.5).
  3. $G_2$ is trained with double the weight on $x_2$. It is strongly incentivised to correctly classify $x_2$. Any stump that perfectly classifies $x_2$ will have low weighted error even if it misclassifies one of $x_1$ or $x_3$ (each with weight 0.25).
Problem 2: Gradient boosting steps Data: $(x_1,y_1)=(1,3)$, $(x_2,y_2)=(2,5)$, $(x_3,y_3)=(3,2)$. Use squared loss and $\nu=0.5$.
  1. Initialise $\hat{f}^{(0)}=\bar{y}$. Compute the initial pseudo-residuals.
  2. A stump fits the residuals and predicts $+2$ for $x_1$, $+2$ for $x_2$, $-2$ for $x_3$. Update $\hat{f}^{(1)}$ and compute new residuals.
  3. How do the new residuals compare to the initial residuals? What has boosting achieved?
  1. $\bar{y}=(3+5+2)/3=10/3\approx 3.33$. $r_1^{(1)}=3-3.33=-0.33$, $r_2^{(1)}=5-3.33=1.67$, $r_3^{(1)}=2-3.33=-1.33$.
  2. $\hat{f}^{(1)}(x_1)=3.33+0.5(2)=4.33$, $\hat{f}^{(1)}(x_2)=3.33+0.5(2)=4.33$, $\hat{f}^{(1)}(x_3)=3.33+0.5(-2)=2.33$. New residuals: $r_1^{(2)}=3-4.33=-1.33$, $r_2^{(2)}=5-4.33=0.67$, $r_3^{(2)}=2-2.33=-0.33$.
  3. $r_2$ decreased from 1.67 to 0.67 (the biggest initial residual was corrected most). $r_1$ and $r_3$ changed slightly. The overall sum of squared residuals decreased: from $0.33^2+1.67^2+1.33^2\approx 0.11+2.79+1.77=4.67$ to $1.33^2+0.67^2+0.33^2\approx 1.77+0.45+0.11=2.33$. Boosting has reduced training loss by roughly half in one step, with more iterations to further reduce the remaining residuals.

XGBoost

Problem 1: XGBoost objective At a leaf with observations $I=\{1,2,3\}$, gradients $g=(2,-1,3)$ and Hessians $h=(1,1,2)$. Set $\lambda=1$.
  1. Compute the optimal leaf weight $w^*$.
  2. If splitting this leaf produces children with $G_L=-1,H_L=1$ and $G_R=5,H_R=3$, compute the split gain with $\lambda=1$ and $\gamma=0$.
  3. At what value of $\gamma$ would this split be rejected?
  1. $G=2+(-1)+3=4$, $H=1+1+2=4$. $w^*=-G/(H+\lambda)=-4/(4+1)=-0.8$.
  2. Parent: $G_j=4$, $H_j=4$. $\text{Gain}=\frac{1}{2}\left[\frac{(-1)^2}{1+1}+\frac{5^2}{3+1}-\frac{4^2}{4+1}\right]-0=\frac{1}{2}\left[\frac{1}{2}+\frac{25}{4}-\frac{16}{5}\right]=\frac{1}{2}[0.5+6.25-3.2]=\frac{1}{2}(3.55)=1.775$.
  3. The split is accepted when Gain $-\gamma>0$, i.e.\ $\gamma<1.775$. For $\gamma\geq 1.775$, the split is rejected.
Problem 2: Conceptual
  1. An XGBoost model achieves training AUC 0.99 and validation AUC 0.72. Which hyperparameters would you adjust first? Justify your answer.
  2. A colleague proposes a column subsampling fraction of $0.3$ with a maximum tree depth of $8$. Explain the bias-variance implications of this combination.
  3. SHAP values for observation $x_5$ sum to $+0.45$. The baseline prediction (mean) is 0.30. What is the model's predicted value for $x_5$?
  1. The large train-validation gap (0.99 vs 0.72) indicates severe overfitting. First priorities: reduce the maximum tree depth (from 6 to 3 or 4), increase the minimum Hessian sum per leaf (e.g.\ to 5 to 10), and reduce the row and column subsampling fractions (e.g.\ to 0.7). Also increase $\lambda$ and $\gamma$. Use early stopping with a patience of 50 rounds to find the optimal number of trees. Reducing the learning rate alone without adjusting tree complexity is less effective for this degree of overfitting.
  2. A column subsampling fraction of $0.3$ means each tree sees only 30% of features: reduces correlation between trees (like a random forest), which reduces variance. A maximum depth of $8$ means very deep trees: each individual tree has low bias but high variance. The combination attempts to balance these two forces: deep trees allow complex function approximation, while low column sampling reduces ensemble variance. However, deep trees with few features can produce unstable splits at lower levels where the available feature set is very restricted. In practice, this combination can work but a depth of 4 to 6 with a column fraction of 0.7 to 0.8 is usually more stable.
  3. $\hat{f}(x_5) = E[\hat{f}] + \sum_j \phi_j(5) = 0.30 + 0.45 = 0.75$.
